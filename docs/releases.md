# Модель релиза

На общем сайте InnoMafia одна установка обслуживает несколько клубов.
Self-hosted клуб использует те же образы API и web со своим доменом,
PostgreSQL и учётными записями.

В CI стартовой версии `sources.json` фиксирует исходники API и web,
из которых собирается тестовый набор. При добавлении публикации GHCR
релизный манифест будет фиксировать digests обоих приложений,
версию контракта и образ PostgreSQL.

Предлагаемый порядок для релиза:

1. Собрать образы приложений и проверить выбранный набор на staging.
2. Сохранить предыдущий манифест и проверить наличие резервной копии PostgreSQL.
3. Один раз применить совместимые миграции из образа API.
4. Запустить тот же набор на production после подтверждения через GitHub Environment.
5. Проверить readiness и сквозной сценарий игры с выгрузкой протокола.

Схема должна допускать запуск предыдущего образа во время окна отката.
Секреты изолируются по окружениям с SOPS и age. Бэкап и восстановление
PostgreSQL проверяются отдельно от отката образов.

Текущий Compose предназначен для локальной разработки и CI. Настройка
TLS-домена, публикации GHCR, staging и production входит в следующий этап.
